## Documented deviation: Linux host

The roadmap's M2.4 line called for the Linux XCB host. Implementation found
that the XCB host has no ImGui platform input backend (none exists in the
repository or upstream ImGui), wires no mouse/keyboard callbacks, and forces
`ImGuiConfigFlags_ViewportsEnable` off; the Vulkan implementation plan
explicitly introduces no new platform input backend. Moving the default Linux
Viewer to XCB would therefore regress the GUI to non-interactive.

M2.4 retains the SDL host for Linux OpenGL selection (zero GUI regression) and
uses the existing XCB path for Vulkan selection, whose GUI limitations are
already tracked in the Vulkan plan. A partial `PlatformVulkanXcb` library
(XcbApplication + VulkanApplication, without the XCB OpenGLApplication or
PlatformAssetIO) lets both hosts coexist in one executable without duplicate
`My::OpenGLApplication` or `AssetLoader::Initialize` symbols. XCB ImGui parity
is recorded in the roadmap as a prerequisite for the agreed XCB-only host.

## Artifact inspection

Direct visual inspection was not available in this session (no image input;
Pillow unavailable in the snap Python environment), so captures were verified
by exact comparison against the accepted pre-M2.4 baseline (pipeline 1088):

- Linux `viewer-screenshots/viewer-render.png`: byte-identical (SHA-256 match,
  651466 bytes) to the 1088 capture.
- Windows: 4452/760984 pixels differ (0.585%) vs 1088; two pre-M2.4 runs
  (1086 vs 1088, identical engine source) differ by 4607 pixels (0.605%).
- macOS: 2726/786432 pixels differ (0.347%) vs 1088; pre-M2.4 baseline
  variation is 2739 pixels (0.348%).

The M2.4 differences are at or below the established run-to-run capture
variation (animation/physics timing), scattered rather than structural, and
the headless GUI/layout regressions pass in the full run. No visual regression
is indicated; interactive native inspection remains part of M2.6 acceptance.

## Limitations

- Successful per-backend startup from one executable (`--rhi` matrix) and
  native `--list-rhi`/explicit-error smoke are not yet exercised by CI; they
  remain M2.6 scope. This run verifies default startup through the new path.
- Windows native OpenGL/Vulkan startup coverage is still not established.
- Billiard keeps its compile-time startup; integration is M2.5.
- Linux Vulkan selection inherits the XCB host's tracked GUI limitations
  (no ImGui platform input, no multi-viewports) until XCB ImGui parity lands.
