## Accepted boundary

ViewerLogic receives a required borrowed `ISceneManager&`. Initialization,
scene cycling and camera callbacks use that service without downcasting
Application or retaining a previous scene/camera. The Viewer composition root
constructs the scene service before logic, preserving the required lifetime.
Application is still used through IApplication for command-line arguments and
quit requests; missing Application at initialization is explicitly rejected.

No Application rewrite, new injection framework, shader changes or Billiard
dependency changes are included. This accepts D4a in the
[modularization roadmap](../architecture/modularization-roadmap.md), not D4b.

## Limitations

Synthetic callbacks do not verify native keyboard/mouse delivery, exhaustive
ImGui focus/capture paths or all camera orientations. The standalone test
isolates the screenshot marker environment; marker I/O is exercised by native
capture gates instead. Linux terminates Viewer after capture, and ordinary
macOS Viewer capture is best-effort; separate Windows/macOS scene-cycle steps
enforce normal exit.

No fix is claimed for existing shadow differences, optional scene assets or
native performance. Android remains disabled. Vulkan, GLES and other unlisted
backends are not accepted here. Billiard scene/physics injection remains D4b.
