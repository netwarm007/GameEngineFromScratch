## Scope

From the [memory allocator roadmap](../architecture/memory-allocator-roadmap.md):
`MemorySystem::StatsReport()` summarizes routing, frame and tracking counters.
The destructor emits it, followed by the tracker's leak report, through
`Config::reportHandler` (default `std::cerr`). With the switch ON, tracking is
enabled in every non-`NDEBUG` build. `MemorySystemTest` covers the report
contents, report order, a leaking shutdown and a clean shutdown (also run
locally under ASan/UBSan and at `-O2`).

## Tested configurations

- Linux and Windows: engine built with `-DUSE_ENGINE_ALLOCATORS=ON
  -DENABLE_ALLOCATOR_TRACKING=ON`.
- macOS: switch OFF (default).

## Limitations

- CI does not inspect the shutdown output of a real application run, so
  "no leaks reported" for the engine itself is not yet demonstrated (M8.6).
- `StatsReport()` is not synchronized with concurrent allocation.
- The ON configuration is not verified on macOS.
