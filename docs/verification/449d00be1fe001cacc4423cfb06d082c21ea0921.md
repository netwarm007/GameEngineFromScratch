Tests included `PhysicsSceneIntegrationTest::TestSplashBouncingBall` (the real
`splash.ogex` with Bullet) and the extended `OgexParserTest`. The Viewer uses
Bullet on all platforms; Billiard backends are unchanged from earlier records.

Exact-revision screenshots were inspected on all three platforms:

- `viewer-render.png`: the ball is visible on the text, panels are docked
  without overlap or clipping, and the scene is inside the main viewport.
  Windows has a mouse-hover texture tooltip that does not cover the ball.
- `billiard-after.png`: table, ball cluster and cue sticks are visible, with no
  regression.

macOS capture: the Viewer previously rendered at about 180 draws/s unpaced and
the ball left the text about 640 ticks after load, so wall-clock captures missed
it (diagnostic logs confirmed the ball batch was drawn and moving). macOS now
captures by GUI frame (`-screenshotFrame 480`), with timed runs paced to 60
ticks/s.

Limitations: a still image shows only one instant; bouncing is evidenced by the
integration test (at least 8 bounces, no drop into word gaps), not by the
screenshots. The ball trajectory is chaotic, so the ball's screenshot position
differs per platform. Local runs could not load LFS textures, so only CI
exercised the Viewer.
