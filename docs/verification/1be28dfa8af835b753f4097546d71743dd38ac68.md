## Accepted boundary

OverlayPass explicitly supplies an image-loading callable to GuiSubPass.
The production LoadGuiIconImage function performs AssetLoader lookup and PNG
decoding. GuiSubPass no longer includes or constructs AssetLoader/PngParser.
The callback is stored by value and must report missing/invalid image failures;
the production implementation preserves those diagnostics. An empty callback
is rejected explicitly.

GuiSubPass retains lazy one-shot loading, existing icon paths/order, fallback
node labels, GPU texture creation/error reporting and GPU icon ownership.
Only successfully created icons are released by GUI teardown, while the
backend remains available. Icons remain separate from scene-owned allocations
and cached debug views. No shader, platform input, docking or asset-framework
rewrite is included.

This accepts D3 in the
[modularization roadmap](../architecture/modularization-roadmap.md), not the
deferred application-service lookup work.

without requiring AssetLoader initialization. The additional ownership case
checks:

- Decoded pixel data reaches texture upload unchanged.
- Missing/failed image results skip upload, and a failed GPU upload does not
  discard successfully created icons.
- Loading occurs once despite repeated frames and scene replacement.
- Destruction before drawing does not load or release icons.
- Partial-success teardown and a fresh GUI lifecycle release successful

## Limitations

Injected failures validate GUI ownership/continuation, not exhaustive malformed
PNG parsing, filesystem races or native driver allocation failure. The default
loader still uses the existing AssetLoader and PNG implementation; DrawSubPass
still links ImageDecoders for that production adapter. This is a dependency
boundary extraction, not full build-target isolation or a new image service.

Native screenshots show the scene kinds present in the existing assets, not
every possible bone-node icon or interactive UI state. Layout scaling/origin
checks are headless; exhaustive native multi-viewport interaction is not claimed.
Linux terminates Viewer after capture; the ordinary macOS Viewer capture is
best-effort. Separate Windows/macOS scene-cycle steps enforce normal exit.
Existing optional scene-asset availability and cross-backend visual differences
are outside D3. Android is disabled; Vulkan, GLES and unlisted backends are not
accepted here.
