## Accepted boundary

- Common scene teardown clears borrowed batches, material cache entries,
  scene references and frame texture bindings, releases tracked scene textures
  once, and empties the ownership collection.
- Metal waits for outstanding submissions and releases/clears scene vertex
  and index buffers. Scene-only retirement retains initialized queues,
  per-frame constants and other persistent backend resources.
- Metal and OpenGL register material, environment, BRDF and shadow allocations
  with scene ownership. Framebuffer targets and UI-owned icons/views remain
  separately owned. D3D12 retains its existing explicit scene cleanup.
- GuiSubPass invalidates cached debug views when the scene changes, even when
  the new scene reuses the same source texture handles and sizes.

This accepts D1 in the
[modularization roadmap](../architecture/modularization-roadmap.md), not the
deferred InputManager or UI-asset dependency changes.

## Regression evidence

The common regression exercises A/B/A and an empty scene with actual shared
geometry-node references, registered textures and a repeated material name.
It checks old reference retirement, fresh material allocation, the exact live
texture count, empty borrowed state and repeated finalization.

## Limitations

Empty-scene and same-name material ownership are checked by the common
regression, not a native pixel-content comparison. The native screenshots use
the existing splash and billiard assets. Metal buffer tracking is not a complete
GPU memory/leak profile or exhaustive allocation-failure/device-loss test.
No performance threshold is claimed.

The ordinary macOS Viewer capture remains best-effort; normal scene-cycle
process exit is established by its separate strict step. Native screenshots do
not replace headless layout coverage or test every interactive multi-viewport
configuration. Android is disabled; Vulkan, GLES and other unlisted backends
are not accepted here.

Earlier attempts were not accepted: pipeline 981 hit a Windows Vulkan SDK
installation timeout; pipeline 982 exposed a null PowerShell process exit code;
pipeline 985 exposed a fixed-delay screenshot race. Pipeline 988 includes the
process-handle and rendered-phase synchronization corrections.
