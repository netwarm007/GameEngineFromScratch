## Ownership boundary and focused regression

GraphicsManager now owns the offscreen single-sample color targets, shared
MSAA color target, and shared depth target separately from the Frame descriptors.
Frames borrow those descriptors and must not release them independently.
Resizing and scene cleanup invalidate the borrowed descriptors and release each
owned target once, including backends that do not clear a released descriptor.
Finalization disables further target allocation by ResizeCanvas.

D3D12 retains its GPU-idle wait and backend-specific scene cleanup, then delegates
offscreen target and frame scene-snapshot cleanup to GraphicsManager instead of
releasing frame aliases itself. Metal performs GraphicsManager cleanup before
finalizing its RHI. Window, device, swapchain, shader, and scheduling contracts
are not redesigned by this checkpoint.

RenderServicesTest uses a recording backend without a real RHI. It checks:

- Distinct single-sample color targets for each in-flight frame and shared
  depth/MSAA targets with the expected dimensions, formats, and sample counts.
- Exact-once release on resize, unchanged/minimized resize suppression, and
  enabling/disabling MSAA without retaining stale descriptors or flags.
- Scene replacement without leaking offscreen targets or retaining old frame
  scene snapshots.
- Final target release, cleared frame aliases, repeated cleanup, and suppression
  of allocation on resize after finalization.
- Safe cleanup after initialization fails for a missing platform application.
- Both handler-backed and buffer-only resource descriptors, with a backend
  release operation that deliberately does not clear the caller's descriptor.

Temporarily restoring the old EndScene per-frame texture release loop made the
new regression fail. Restoring the ownership-based cleanup returned it to
passing. Five local Windows Debug regressions passed: RenderServicesTest,
SceneCameraTest, SceneLightingTest, GuiSubPassLayoutTest, and
RuntimeModuleLifecycleTest. These used the existing session-local CMake harness
selecting production libraries and test targets. Full local application
configuration lacked prebuilt dependencies, so real backend/application checks
used the exact-revision CI builds instead.

## Limitations

The allocation/release counting regression is backend-independent; screenshots
do not establish exact GPU allocation counts or exercise every native resize
and scene-switch path. Missing-application initialization failure is covered,
not injected device or GPU allocation failures. General scene texture ownership,
platform window/device/swapchain lifetime separation, and ImGui lifecycle
separation remain subsequent work.

Windows OpenGL, Android, WebAssembly, Vulkan, CUDA, and other unlisted
configurations were not verified. This record verifies only the source revision
above, not the documentation-only commit adding this file or any later merge.
