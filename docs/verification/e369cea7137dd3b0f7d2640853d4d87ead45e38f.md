## Vulkan resource evidence

The retained llvmpipe CTest log reports passing `TEST_VulkanShaderAbi`,
`TEST_VulkanCompute`, `TEST_VulkanResources`, and `TEST_VulkanFrameLoop`, with no
validation-error/VUID markers.

The new resource test uses the production VulkanRHI through explicit headless
initialization, not a separate resource implementation or automatic WSI
fallback. It checks:

- GPU vertex/index byte readback and transactional rejection of an invalid
  uniform allocation.
- Uniform strides from the actual physical-device alignment, independent arena
  slices, upload bounds, and GPU readback of data plus preserved gaps.
- Array and twelve cube-array faces, generated mips against independent CPU
  color expectations, retained base levels, and selected subresource updates.
- Supplied mip chains with deliberately distinct values, padded RGBA/RGB rows,
  signed normalized RGB expansion/alpha, and GPU readback.
- Rejection and rollback after an invalid later mip, repeated shutdown, and
  validation through resource/device destruction.

The native frame loop still covers selected initialization failures/retry,
bounded submissions through the presentation path, resize, deferred
minimize/restore, and repeated shutdown on Xcb/Xvfb. It does not render shared
engine scene passes.

## Limitations

- Linux Vulkan uses a software driver. Windows production-RHI resource readback
  also passed locally on AMD Radeon(TM) Graphics, but Windows Vulkan WSI remains
  unverified; its earlier native query returned `VK_ERROR_UNKNOWN`.
- MoltenVK/Cocoa Vulkan compilation and execution are not established by the
  native Metal job.
- This revision still uses device-idle waits to retire swapchains. It does not
  meet the subsequently chosen strict presentation-fence requirement; normal
  per-image semaphore reuse and old-layer validation do not prove retirement.
- Resource readback does not verify graphics descriptor binding, shared
  per-frame/per-batch shader consumption, point-shadow face/layer rendering,
  Vulkan Viewer/Billiard scenes, ImGui, multi-viewports, or MSAA rendering.
- Compressed-format transfer code and all declared native image formats are not
  exhaustively exercised by the uncompressed resource fixtures.
- Disabled Android is not covered.

This record verifies only this source revision, not the documentation-only
record commit, subsequent retirement changes, or any merge.
