# Framework asset-parser security hardening

Tested source revision: `3e4353be44215c763a6bad1e7589e5bb817abbb4`.

This revision carries the security audit remediation of `Framework/`:
11 findings (1 CRITICAL, 7 HIGH, 3 MEDIUM) across the JPEG, PNG, HDR, TGA,
DDS, ASTC and WAVE parsers plus `AssetLoader` path handling. The parsers
previously validated file-derived sizes and indices with `assert()`, which
is compiled out in Release builds, so malformed assets caused
out-of-bounds reads/writes. They now reject malformed input with hard
bounds checks (the pattern already used by BMP/PVR) and return an empty
Image/AudioClip. `AssetLoader` gained `IsSafeAssetPath()` (rejects
absolute/drive/UNC/`..` paths), a 512 MB asset cap, and fixed `fread`
argument order. The new headless regression test
`Test/Parser/ParserHardeningTest.cpp` (ctest label `fast`) covers every
rejection path. Follow-up review fixes on this same branch: the TGA
over-strict alpha-depth equality check that wrongly rejected the shipped
32bpp RGBX `icelogo-*.tga` assets (`f441ca92`), and the JPEG
restart-interval boundary `assert` replaced by a stderr diagnostic
(`3e4353be`, pre-existing; Release behavior unchanged). HDR additionally
now writes each RLE scanline to its own row instead of overwriting row 0,
and literal runs follow the spec's `count`-total semantics; both are
intentional output changes verified against an independent reference
decoder.

## Focused local verification (same revision)

- Byte-identical output vs the pre-hardening parsers on real assets
  (FNV hashes over decoded pixels): JPEG `a3c7a4c5`, PNG `10a23425`,
  TGA `cfeee3cd`, DDS `a6002494`, ASTC `0dcd900e`, WAV `84d79821`.
  All 87 repo TGAs match byte-for-byte; only the two `icelogo-*.tga`
  metadata labels differ (RGB8 to RGBA8 correction, pixels unchanged).
  HDR intentionally differs: the new decoder matches an independent
  reference decoder (the old parser wrote every RLE row to row 0).
- Corrupted-input sweep (truncations, bit flips, saturated header
  fields): the pre-hardening parsers crashed (0xC0000005, 0xC0000409);
  the hardened parsers completed every case with exit 0, no crash.
- Debug (asserts live) sweep over all 200 sweep assets: no assert trips;
  `ParserHardeningTest` passes in Debug and Release.

## Remaining limitations

- The parser regression suite is headless unit coverage over crafted
  buffers; the native captures above prove the real scene asset pipeline
  still loads and renders, but do not force every malformed-input path
  through a live backend.
- The `icelogo-*.tga` RGBX label correction is not exercised by any
  shipped scene (no scene references those textures); it is covered by
  `ParserHardeningTest` instead.
- The JPEG restart-interval resync logs a diagnostic when an interval
  ends early (9 of the 20 shipped JPEGs); the pre-existing truncation of
  remaining MCU data at that boundary was not changed by this revision.
- Linux is software OpenGL, not hardware-driver validation. Its Viewer
  capture script terminates the application after capture; it does not
  prove normal Viewer shutdown. Ordinary macOS Viewer capture is
  best-effort; its actual PNG was checked rather than inferred from the
  step result.
- Screenshots do not certify every debug thumbnail, native input/focus
  paths, performance, or animation/pixel equivalence. Windows captures
  show low frame rates and hover tooltips.
- Android is disabled. Native Vulkan, GLES, unlisted devices/backends and
  future merge revisions are not verified here.
