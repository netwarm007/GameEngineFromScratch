## Shared shader ABI and compute evidence

The isolated Vulkan job built the repository-pinned glslang and SPIRV-Cross.
All 24 production stages, generated from shared HLSL, passed original-binary
SPIR-V validation, reflected active descriptor/buffer-layout checks, and
relevant stage-interface checks. Vertex-layer capability inspection covers the
instanced omni stage but does not execute its graphics pipeline.

An additional unoptimized basic vertex fixture exercises inactive shared b13
declarations. Reflection uses a dead-code/unused-variable-stripped test copy;
production binaries are not modified by the check. Removing this normalization
locally made the fixture fail with the original inactive-binding collision;
restoring it passed. A separate local negative control without Vulkan binding
shifts also failed as expected.

The compute test ran on Mesa llvmpipe (LLVM 15.0.7, 256 bits), with reported
`minUniformBufferOffsetAlignment=16`. It checked shared uniform/matrix data by
GPU readback and dispatched the production BRDF shader over the full 512x512 LUT.
Four distributed RG samples matched independent double-precision CPU integration
within 0.001 per channel; repeated BA channels were also checked:

| Pixel | R | G |
| --- | --- | --- |
| (63, 255) | 0.583140 | 0.091496 |
| (255, 127) | 0.900598 | 0.0304394 |
| (447, 383) | 0.592035 | 0.000436829 |
| (511, 511) | 0.307307 | 0.0000336136 |

The compute test completed in 5.26 seconds with Khronos core and synchronization
validation enabled and no reported validation errors, including resource/device
destruction. This is correctness evidence, not a hardware performance claim.
The same focused suite passed locally on Windows with Vulkan SDK 1.2.182
(glslang 11.5) and AMD Radeon(TM) Graphics.

## Native application artifact observations

The actual Viewer and Billiard PNGs from all three native jobs were opened.
Each shows a rendered scene, docked scene tree, and docked debug panel within the
application viewport. No new docked-panel overlap or placement outside the
viewport was observed. Windows retains the hover magnifier overlay on part of
the scene. Viewer shows the shared splash scene and colored shadows; the
animated sphere differs in position between platforms. Billiard shows the table,
balls, cues, and environment on every backend.

The macOS shadow preview thumbnails are white in these captures. Its logs report
missing CubeMap Debug Output and CubeMap Array Debug Output shader functions,
as well as drawable presentation/lifetime diagnostics. These diagnostics were
not resolved by this shader checkpoint. Successful scene captures do not verify
those debug pipelines or prove correct drawable lifetime in every situation.

## Scope and limitations

- CI Vulkan runtime coverage is Linux software compute only. Windows Vulkan
  compute was tested locally, not in this pipeline; macOS/MoltenVK Vulkan
  execution was not tested.
- The headless harness exercises the shader ABI directly, not VulkanRHI device,
  frame, swapchain, upload, resize, or presentation integration.
- Uniform descriptors use offset zero; dynamic uniform allocation/stride and
  device-specific lifetime behavior remain checkpoint 2 work.
- Vulkan graphics pipelines, point-shadow face/layer execution, rendered
  Viewer/Billiard output, MSAA, ImGui rendering, floating viewports, and
  portability fallbacks are not verified by this checkpoint.
- Native screenshots are limited regression samples, not exhaustive lighting,
  shadow-face, debug-texture, or device coverage.
- The additional Vulkan job runs in the branch workflow, not the release/tag
  workflow.

This record verifies only the tested source revision, not its later
documentation-only record commit or any merge revision.
