## Integration and retained behavior

Master already contains the earlier offscreen ownership, desktop shutdown, and
initialization rollback foundations through PR #61. This integration preserves
those implementations and the upstream generic runtime-module registration API.
It also preserves the Splash animation-before-physics sequence, geometry
visibility behavior, and shadow-upload/culling work from subsequent upstream
changes. The upstream shadow upload-order regressions remain in
RenderServicesTest.

The topic's additional work remains the stage A window/backend initialization
boundary and stage B selected native initialization failure/cleanup guarantees:

- Native window creation precedes backend initialization and module startup.
- GLX failure paths return errors, clean partial native resources, restore the
  prior X error handler, and preserve legacy context fallback.
- D3D12 setup errors propagate before module startup; partial event allocation
  unwinds safely, closed handles are invalidated, and cleanup callbacks run once.
- A gated native D3D12 command-list submission completes before module rollback.
- Metal checks selected native initialization allocations, releases its own
  partial resources, and supports repeated cleanup and deliberate RHI retry.

Conflict resolution retains the stage A/B hooks and extended native tests
without dropping the upstream module API, shadow regressions, or visibility
changes. No submodule revision was changed.

Detailed failure coverage and negative controls are preserved in the
[stage B record](b95495ed37f5d2864a0dc56a7721a0c063c1c22b.md) and
[GLX record](a9c7cdba1cc4af16f800c76248a7364db38b470b.md).
Those records describe their own revisions; this document verifies the combined
merge revision above.
