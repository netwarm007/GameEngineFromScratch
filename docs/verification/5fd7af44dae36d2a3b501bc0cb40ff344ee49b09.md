## Scope

From the [memory allocator roadmap](../architecture/memory-allocator-roadmap.md):
`MemorySystem` now owns a `FrameAllocator` (1 MiB per frame, two frames)
exposed as the pmr resource `FrameResource()`; `BaseApplication::Tick` calls
`BeginFrame()` each tick. The pilot site is the per-draw vertex-buffer-view
scratch vector in `D3d12GraphicsManager::DrawBatch`, now a `std::pmr::vector`
reused across draws (default resource when the switch is OFF). `D3dRHI` links
`Manager`. `MemorySystemTest` covers pmr containers on the arena, rotation
and recycling, exhaustion (`std::bad_alloc`) and page return;
`ApplicationLifetimeTest` checks one new arena per tick. `MemorySystemTest` also
ran locally under ASan/UBSan and at `-O2` on Linux.

## Tested configurations

- Linux and Windows: engine built with `-DUSE_ENGINE_ALLOCATORS=ON
  -DENABLE_ALLOCATOR_TRACKING=ON`.
- macOS: switch OFF (default).

## Limitations

- The D3D12 pilot path compiled on Windows CI, but no D3D12 rendering or
  screenshot was inspected for this revision; CI does not demonstrate
  identical frames with the switch ON.
- The frame arena is fixed at 1 MiB per frame with no fallback on exhaustion.
- The ON configuration is not verified on macOS.
