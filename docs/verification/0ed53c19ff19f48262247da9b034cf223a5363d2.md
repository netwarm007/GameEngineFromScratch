## Focused Vulkan evidence

All seven standalone tests passed: shader ABI, compute, resources, pipelines,
graphics, GUI, and native frame loop.

- GUI checks cover sampled image orientation, clipping, dynamic fonts, depth
  preview filtering, stale identities, initialization rejection/rollback/retry,
  repeated finalization, and preservation of borrowed context state.
- Manager integration covers real engine texture registration, padded updates,
  parent-retaining subresource views, lazy uploads during recording, deferred
  resize, and alias-aware transfer rejection.
- Resource tests verify RGB16 normalized/signed/half-float and RGB32 float
  expansion into matching RGBA storage, including padded rows and supplied
  mips, using actual GPU readback.
- A known BC1 block is sampled through the production texture/GUI path.
  Its output preserves the encoded UNORM values; the regression failed before
  removing the unintended sRGB decode.
- Native coverage includes main/secondary resize, secondary destruction and
  recreation, two renderer lifetimes, maintenance1 presentation retirement,
  and framebuffer byte-count/color/orientation checks.
- Existing shared rendering checks still cover BASIC/PBR, MSAA, environment,
  six sky directions, four shadow-receiver cases, and 24 point-shadow
  face/depth comparisons.

## Limits and follow-ups

- Windows Vulkan WSI and MoltenVK runtime, floating-window input/lifecycle, and
  Retina scaling remain unverified. Win32 adapter syntax and Cocoa compilation
  are not runtime acceptance.
- Xcb platform input still disables ImGui multi-viewports. The native regression
  directly drives secondary-renderer callbacks; it does not establish Linux
  floating-window input support.
- Base-only material uploads currently retain one mip. Supplied mip chains and
  explicit uncompressed mip generation work, but automatic material mip
  generation needs parity work before full renderer acceptance. Track it under
  checkpoint 3 with follow-up in checkpoint 5 of the
  [implementation plan](../architecture/vulkan-rhi-implementation-plan.md).
- Native presentation still requires maintenance1 fences; no device-idle
  presentation-retirement fallback was added. Secondary presents wait their
  scoped fences synchronously. No general device-loss recovery is claimed.
- Capture requires transfer-source swapchain support and an RGBA8/BGRA8 UNORM
  presentation surface; application output is PPM, not PNG.
- Local Windows validation passed the six runnable headless GPU/ABI tests.
  Header changes used a clean rebuild; subsequent source-only fixes used
  targeted rebuilds. Its installed SDK 1.2.182 cannot run the strict native frame loop; the
  full local application build was blocked by missing prebuilt dependencies.
  CI, not those local limitations, supplies the native reference evidence above.
