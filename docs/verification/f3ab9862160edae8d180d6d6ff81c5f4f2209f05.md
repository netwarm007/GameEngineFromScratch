## Initialization boundary

Desktop graphics clients now create the native window before Initialize.
BaseApplication then invokes InitializeGraphicsResources before initializing
runtime modules. It retains successful backend setup across module failure
rollback/retry and resets that state during finalization. A backend-hook error
is logged and returned before any module initializes. Callers still invoke
Finalize after initialization failure to release outer resources.

The existing D3D12, Windows OpenGL, and Vulkan setup sequences move out of
CreateMainWindow into the hook; D2D moves its RHI callback binding. Linux keeps
framebuffer configuration discovery as window preparation, but creates the
GLX context/drawable during initialization. macOS prepares the Metal view/device
in the hook; Metal2GraphicsManager still owns its RHI initialization. macOS
Vulkan invokes the Metal-view hook before creating its surface.

Existing shutdown ordering remains GPU synchronization, reverse module cleanup,
backend destruction, then native window cleanup. Rendering configuration,
shader/coordinate conventions, frame scheduling, and ImGui ownership are not
redesigned. Legacy BasicWindow and standalone RHI test entry points now create
their windows before initialization; RHI initialization is evaluated outside
assertions so it is not suppressed by NDEBUG.

## Focused regression

ApplicationLifetimeTest models separate window and backend lifetimes. It checks:

- Window creation alone does not initialize graphics.
- Backend initialization precedes every module initialization.
- Missing-window and backend-hook errors prevent module initialization/ticks.
- Explicit failure cleanup releases modeled partial backend resources before
  the window; a new lifecycle can subsequently initialize successfully.
- Module rollback/retry and repeated-initialization rejection do not recreate
  an already initialized backend.
- Finalization resets successful backend initialization state for a new lifecycle.
- Existing reverse cleanup and pre-rollback GPU synchronization remain intact.

Temporarily removing the backend initialization orchestration made the regression
fail. Restoring it returned ApplicationLifetimeTest, RenderServicesTest, and
RuntimeModuleLifecycleTest to passing in the local Windows Debug CMake harness.
Changed Windows D3D12, D2D, and OpenGL application implementations and the
D3d12GuiTexture test also passed MSVC syntax checking.

The exact-revision native Windows D3d12GuiTexture test checks that a window
exists without a D3D12 device before Initialize, then exercises graphics texture
creation after module initialization. The Linux native test checks the analogous
absence of a GLX context after window creation, its presence during module
initialization and cleanup, cleared final handles, and repeated shutdown.

## Limitations

Backend-hook failure is modeled, not injected into native device or allocation
setup. Existing native setup assertions, exceptions, and partial-allocation
cleanup behavior remain; this checkpoint does not establish general recovery
from native initialization failure. Linux display/framebuffer-selection internals
and ImGui platform/view ownership are not redesigned.

Windows OpenGL, D2D, Vulkan, SDL, Android, WebAssembly, and other unlisted
configurations were not runtime-verified. Android remains disabled in CircleCI.
This record verifies only the full source revision above, not the
documentation-only commit adding it or a later merge. No PR was created for
this intermediate checkpoint.
