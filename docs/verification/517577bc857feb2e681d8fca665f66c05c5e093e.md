## Shutdown boundary and regression coverage

BaseApplication now coordinates explicit shutdown phases:

1. Synchronize outstanding graphics work where the backend requires it.
2. Finalize initialized runtime modules in reverse order.
3. Destroy backend resources.
4. Release the native platform window and connection.

Desktop applications implement the relevant synchronization, graphics cleanup,
and platform cleanup hooks rather than duplicating nested Finalize calls.
Windows D3D12 waits for idle before any module can release pipeline objects,
but keeps the device and swapchain until module cleanup finishes. Cocoa retains
its window during module/backend cleanup. XCB now participates in module
cleanup before closing its window and connections. Linux OpenGL propagates
the parent initialization error instead of reporting unconditional success.

ApplicationLifetimeTest uses production BaseApplication with recording modules.
It checks synchronization before resource release, reverse module shutdown,
backend-before-window cleanup, preserved initialization errors and rollback at
each module position, suppression of ticks after failure/shutdown, and cleanup
for window-only clients. Temporarily moving backend/platform cleanup ahead of
modules made the lifecycle regression fail. Temporarily removing the new
pre-module synchronization also failed, including the assertion that GPU work
must finish before modules release referenced resources.

LinuxApplicationLifetimeTest creates a real GLX context and XCB window under
Xvfb with software rendering. A module verifies that both remain available
during its cleanup; the test then checks cleared handles and repeated shutdown.

Three focused local Windows Debug regressions passed:

## Failures found before acceptance

Earlier iterations were not accepted:

- Pipeline 930 exposed Linux `GLXBadWindow` during Billiard shutdown. GLX
  destruction was queued on an Xlib connection while the native window was
  destroyed through a separate XCB connection. Synchronizing Xlib after GLX
  destruction ensures those requests finish before native window teardown.
- Pipeline 931 verified that Linux fix, but Windows Billiard still failed on
  exit: a root signature was released before the GPU finished using it.
  Removing the old early swapchain destruction had also removed its implicit
  pre-module wait. A dedicated D3D12 idle hook restores synchronization without
  prematurely destroying the swapchain or changing module registration order.

In pipeline 932 the Billiard steps completed successfully on all platforms,
including Windows process-exit validation. Viewer and Billiard application logs
were checked for the known D3D12 deleted-object and GLX teardown failure
signatures; neither remained. This is a targeted log check, not a claim that
every possible driver diagnostic was exhaustively audited.

## Limitations

Module initialization rollback is covered without submitted GPU work; native
device/context/allocation failure injection and asynchronous GPU work during
failed initialization were not tested. Backend initialization and ImGui
ownership were not redesigned. The real repeated-shutdown check covers Linux,
not every native backend.

Windows OpenGL, D2D, Vulkan, Android, WebAssembly, SDL, and other unlisted
configurations were not runtime-verified. Enabled acceptance platforms are
Windows, Linux, and macOS; disabled Android is not part of this gate.

This record verifies only the source revision above, not the documentation-only
commit adding it or a later merge. This intermediate checkpoint does not
require creation of a pull request.
