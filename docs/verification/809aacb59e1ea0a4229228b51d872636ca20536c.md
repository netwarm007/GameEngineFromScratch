## What this revision changes

- `RhiStartup` (Framework/Manager) parses `--rhi`/`--rhi=`/`--list-rhi` with
  canonical `d3d12`/`opengl`/`metal`/`vulkan` names, rejects unknown, empty,
  and repeated selections, respects `--`, and preserves borrowed application
  arguments. Resolution distinguishes not compiled, runtime unavailable, and
  ready to attempt initialization, and never falls back to another backend.
  `TEST_RhiStartupTest` (`fast`) covers the production parsing/resolution.
- `VulkanLoader` (RHI/Vulkan) late-loads the platform Vulkan runtime
  (`libvulkan.so.1`, `libvulkan.1.dylib`, `vulkan-1.dll`) and validates the
  instance entry points. Vulkan-Hpp uses dynamic dispatch initialized from the
  loader under a single active dispatch context; platform surface creation and
  ImGui `GetProcAddress` resolve through the loader, including exported WSI
  trampolines. `TEST_VulkanLoaderTest` (`fast`) exercises absent and incomplete
  runtimes, repeated load/teardown, and WSI trampoline resolution using fixture
  libraries, without a Vulkan driver.
- Non-Vulkan startup no longer has a load-time dependency on the Vulkan
  runtime: `VulkanRHI` and the platform Vulkan paths link the static loader
  instead of `Vulkan::Vulkan`, and the loader is only touched on demand.

## Limitations

- Application CLI wiring, real per-backend startup selection, and owned
  factories are not in this revision; Viewer and Billiard keep their existing
  compile-time startup paths. Runtime selection is not advertised.
- The driverless fixture tests demonstrate absent-runtime behavior; the full
  platform jobs still run their existing default backends, so native evidence
  of selecting each backend from one executable lands with M2.4-M2.6.
- Windows native Vulkan/OpenGL startup coverage is not established by SDK
  installation or by the Linux-specific Vulkan job; it remains M2.6 scope.
- The single active Vulkan dispatch context intentionally rejects a second
  simultaneous Vulkan RHI; multi-backend simultaneous rendering is outside the
  first-release contract.
- The Windows sccache change in the tested revision is CI infrastructure; its
  first run populated the cache. Cache-hit timing benefits are not a source
  behavior claim of this record.
