## Observations

- Windows restored both the Debug and the Release dependency caches; neither
  dependency build step appeared among its long steps. Windows took about
  1789 s, against 2109 s for the run that populated the caches.
- Linux restored the Release dependency cache and skipped the roughly 160 s
  Release dependency build; its Debug dependency step still ran (about 120 s)
  because only the Release step is cached on Linux.
- Source (`.git`) and ccache caches are saved only from `master`, so on this
  branch submodule initialization still took 216-343 s per job; those caches
  are expected to help only after the first `master` run seeds them.
- An earlier run of the same tree (`b97179ffdd500e722e677c00a84a48b49036c055`)
  had its Windows job fail in the first step because `cmake` was missing on the
  runner; that is not a result for this revision and was not counted.

## Limitations

The source and ccache cache hits are not exercised by this record. Android
remains disabled; Emscripten/WebAssembly, FreeBSD, CUDA and OptiX are not
accepted by this record.
