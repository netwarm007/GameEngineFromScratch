## Backport and lifecycle evidence

The ImGui gitlink remains
`b916186e66aa3c02b72c6ca17455516512ed8049`; no dependency-wide upgrade or dirty
submodule patch is required. The
[versioned patch and provenance](../../External/patches/README.md) distinguish
the upstream removal of pre-acquire transitions from the local compatibility
change to the old pin's dynamic clear/discard barrier. Production and standalone
tests use the same hash-checked build-copy preparation entry point.

The new `TEST_VulkanSwapchainLifecycle` passed on both explicit Vulkan jobs.
It executes the selected backend's actual helper/renderer callbacks with typed
test-only dispatch for:

- Initial creation and first use, explicit resize, and destruction/recreation.
- `VK_ERROR_OUT_OF_DATE_KHR` deferred rebuild and `VK_SUBOPTIMAL_KHR` rebuild.
- No command recording during unacquired resource preparation.
- Acquired-image semaphore waits on render submission.
- Dynamic clear/discard from `UNDEFINED`, the correct acquired image, and the
  post-render transition to `PRESENT_SRC_KHR`.

Neither explicit Vulkan test log contains the old-header
`Dynamic rendering execution unavailable` message. The dynamic branch includes
the twelve-transition assertion, so these modern-header runs extend the local
old-SDK CPU result to that branch. This is simulated-dispatch lifecycle
coverage, **not real dynamic-rendering GPU or WSI acceptance**.
The same pre-acquire recording check failed against the unchanged old helper
in the preceding local negative control.

`TEST_VulkanFrameLoop` passed on both explicit native CI paths, including the
new secondary create/resize/recreate validation-stage assertions and the
existing main/secondary rollback, retry, resize, minimize/abort, repeated
lifetimes, and strict maintenance-aware presentation-fence retirement.
The MoltenVK native test again reported backing scale 1, not physical Retina.
No engine presentation-fence or retirement code was weakened by this fix.
