## Vulkan evidence

The llvmpipe CTest artifact reports passing `TEST_VulkanShaderAbi`,
`TEST_VulkanCompute`, `TEST_VulkanResources`, `TEST_VulkanPipelines`,
`TEST_VulkanGraphics`, and `TEST_VulkanFrameLoop`, with zero
validation-error/VUID markers.

The new graphics regression uses the production VulkanGraphicsManager, RHI,
pipeline manager, asset loader, and unchanged shared BRDFIntegrator:

- The real GraphicsManager::BeginScene scheduler executes the BRDF initialization
  pass before allocating shared shadow arrays and borrowed per-frame targets.
  An empty scene without a skybox avoids claiming unimplemented draw paths.
- GPU samples from the 512-by-512 BRDF output match the independent CPU reference
  within 0.001, including repeated red/green channels. Selected interior samples
  are checked; this is not exhaustive numerical verification of LUT boundaries.
- The engine's logical RG32 descriptor is backed by RGBA32F Vulkan storage,
  matching the verified shared HLSL/SPIR-V `float4`/rgba32f ABI. Shader math is
  unchanged. Dispatch transitions writes to shader-read layout before returning.
- Invalid compute sequencing, missing storage output, unsupported storage slots,
  mismatched output dimensions, stale texture descriptors, and a finalized
  pipeline registry are rejected explicitly.
- Scene-global textures borrowed by multiple frames are released once.
  Independently owned textures survive scene teardown. Each frame has a distinct
  offscreen color target and borrows the shared depth target.
- Resize replaces offscreen targets without replacing scene globals. Scene
  teardown/reload and repeated finalize/reinitialize invalidate old handles and
  recreate the checked BRDF output.
- Actual single-sample color/depth and shadow array/cube-array allocations are
  exercised. This is allocation/lifetime evidence, not shadow depth or sampling
  evidence. Unimplemented multisample generation fails instead of downgrading.

Five headless tests also passed locally on Windows AMD. Native local WSI remains
unverified because the installed SDK lacks the required maintenance headers.
The existing pipeline/offscreen and strict native-presentation regressions
remain passing in Linux software-Vulkan CI.

## Limitations

- Shared compute dispatch is synchronous initialization work. Integration with
  normal frame command recording remains pending.
- BASIC/PBR scene draws, material/frame/light bindings, skybox rendering, shadow
  depth/sampling for all six faces and multiple lights, and MSAA remain pending.
- Vertex-layer feature enablement or the shared single-face adaptation remains
  required for the non-geometry shadow path.
- Vulkan applications and ImGui rendering are not verified by the shared
  initialization test; it creates no ImGui context or window.
- Vulkan CI uses software rendering with Xcb/Xvfb. Native Windows Vulkan WSI
  and MoltenVK/Cocoa remain unverified. Metal CI does not verify MoltenVK.
- Disabled Android is not covered.
