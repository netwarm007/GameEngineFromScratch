## Accepted boundary

InputManager receives a required borrowed `IGameLogic&` at construction.
Viewer and Billiard supply their existing game logic, whose object lifetime
outlasts InputManager. Input event forwarding no longer downcasts Application
or retrieves its game logic. There are no current InputManager construction
sites without that dependency.

Arrow-down callbacks still occur for every down event, followed by the
first-press callback only when the corresponding key is not held. Releases
rearm that key independently. The `u` button mapping, reserved `d`/`r` no-ops,
mouse button no-ops, drag analog IDs and signed deltas are preserved.
Initialization/finalization reset held keys without emitting callbacks.

No platform event routing or ImGui capture logic changed. This accepts the D2
boundary in the [roadmap](../architecture/modularization-roadmap.md), not a new
event bus, configurable bindings or the deferred UI-asset dependency work.

## Limitations

Input coverage directly invokes InputManager with a recording game-logic
implementation. It does not inject native OS keyboard/mouse events or verify
every ImGui input-capture/focus configuration. Rendered visibility and physics
regressions are separate evidence, not proof of interactive input delivery.

Linux intentionally terminates Viewer after capture; the ordinary macOS Viewer
capture is best-effort. Separate Windows/macOS scene-cycle steps enforce normal
process exit. Existing optional asset availability and backend visual
differences are not addressed. Android is disabled; Vulkan, GLES and other
unlisted configurations are not accepted here.

The documentation-only commit carrying this record uses `[ci skip]`; it does
not verify its own source revision or a later merge revision.
