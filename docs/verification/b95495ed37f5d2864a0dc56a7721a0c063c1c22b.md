## Completed scope

This closes the selected native failure stages in
[roadmap stage B](../architecture/modularization-roadmap.md), following the
[previous GLX checkpoint](a9c7cdba1cc4af16f800c76248a7364db38b470b.md).
The complete GLX regression also passes on this combined source revision.

### D3D12

Native initialization HRESULT failures now propagate as explicit system errors
instead of assertions/process termination. D3d12Application reports the failing
operation, releases partial RHI resources while its window remains alive, and
returns a nonzero result without starting modules. Temporary adapter/swapchain
interfaces use scoped COM ownership. Optional debug setup and object labels
remain optional; runtime device-loss recovery is not introduced.

Fence-event creation is checked one allocation at a time. Cleanup closes only
valid handles and invalidates them, consumes a registered resource-destruction
callback once, and clears released tracked buffers. The graphics-idle guard
rejects both null and invalid event handles.

The native regression injects failure at each of the three event allocations
after a real device, queues, swapchain, and fence have been created. It checks
the exact error, no module startup/ticks, immediate device/event cleanup,
preservation of the native window until Finalize, repeated cleanup, and
successful initialization after explicit cleanup/window recreation. A sentinel
event catches stale-handle closure during repeated Finalize. A registered
resource callback must run once.

A separate case submits an actual command list and completion-fence signal
behind a GPU queue wait. A delayed CPU fence signal releases that gate. Failure
of a later module must wait for native GPU completion before the earlier
module's rollback releases its command allocator/list/fences. This is native
queue execution, not just a modeled pending-work flag; it is not device-removal
or failed GPU-command injection.

Two local negative controls were run and restored before committing:

- Removing immediate failure cleanup failed with the device still alive.
- Removing pre-rollback GPU synchronization failed the gated native completion
  assertion.

After restoration, the native test and ApplicationLifetimeTest,
RenderServicesTest, and RuntimeModuleLifecycleTest all passed locally on
Windows, and the final native test passed in Windows CI.

### Metal

Metal RHI initialization checks per-frame uniform/light buffers, the sampler,
command queue, and initial command buffers. A failed allocation reports its
stage, releases its own partial resources, and returns failure. Cleanup is
repeatable, guards renderer shutdown by successful initialization, waits for
submitted tracked frame buffers before releasing them, and releases owned
initialization buffers, sampler, queue, and command-buffer references.
Deallocation also releases per-frame semaphores and screenshot strings.
Command buffers retained across autorelease pools have balanced ownership.

Metal2GraphicsManager stops immediately if its base initializer fails, returns
failure if its RHI cannot initialize, unwinds its own base/backend state, and
releases/nulls its RHI during cleanup. CocoaMetalApplication checks the newly
created view/device before installation and balances its local view ownership.
ImGui context ownership is unchanged; RHI startup requires a live, unbound
context, and repeated RHI initialization is rejected explicitly.

The macOS native regression forwards through a real Metal device while returning
nil at each selected allocation, including initial command-buffer allocation.
Tracked forwarding resources must be released after failure and autorelease-pool
drain. Every selected failure position is reached, explicit repeated cleanup is
safe, and the same RHI can initialize after the injected failure is removed.
Success, repeated-initialization rejection, finalization, and deallocation
leave no tracked native initialization resources alive. Missing-application
manager initialization is also rejected safely.

Metal production and regression code were built and executed in macOS CI, not
on the local Windows host. The initial source `abd301a7608a255252c7bb6c620cdbbadc064730`
failed macOS compilation in pipeline 951 because the new test lacked its direct
ImGui header. That test-only dependency was corrected before this accepted
revision. Pipeline 951 is not an acceptance record or a behavioral negative
control for Metal.

## Limitations

Failure injection covers the selected API boundaries, not all driver
allocations, resource exhaustion, concurrent initialization, device loss, or
GPU execution faults. D3D12 HRESULT paths beyond event creation were not each
independently fault-injected. Metal tests native RHI retry, not a complete
application/module-graph restart or every scene-resource allocation. Metal
failure after submitted GPU work was not independently injected. Broader
ImGui ownership/cache lifecycle remains stage C.

GLX display opening/framebuffer selection and unlisted backends remain outside
this checkpoint. Windows OpenGL, D2D, Vulkan, Android, SDL, and WebAssembly were
not runtime-verified. Android remains disabled in CircleCI.

This verifies the named source revision only, not the documentation-only commit
adding this record or a later merge. The topic branch remains unmerged; no PR
was created for this checkpoint.
