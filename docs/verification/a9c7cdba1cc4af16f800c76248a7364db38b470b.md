## Failure handling and resource ownership

Linux OpenGL initialization now rejects failed GLX drawable creation, context
creation, and context binding before starting runtime modules. Key calls are
synchronized to observe asynchronous X errors. Failure reports an error, releases
partially created GLX resources while the display/window still exist, and returns
a nonzero result. A scoped guard restores the previous X error handler on exit.
Cleanup unbinds the application's context only if it is current; a missing
context prevents entry to the platform/rendering frame loop.

The existing fallback from attribute-based context creation to the legacy
context API remains. XCB window creation now reuses an already opened Xlib
Display instead of overwriting it: selected GLXFBConfig handles must remain
paired with the Display used to query them. The framebuffer-configuration array
is freed after selection. The separate XCB connection and GLX-before-window
shutdown synchronization remain.

## Native regression and negative evidence

LinuxApplicationLifetimeTest runs under Xvfb with software rendering. Scoped
GLAD function-pointer replacements inject:

1. A null drawable result.
2. A real allocated GLX drawable followed by a queued asynchronous X error.
3. Failure of both attribute-based and legacy context creation.
4. Context binding failure after real drawable/context allocation.
5. Attribute-based creation failure followed by successful native legacy fallback.

Failure cases check nonzero initialization results, no module initialization
or ticks, immediate exact-once cleanup of the expected real allocations,
restoration of the prior X error handler, and preservation of the native window
until explicit finalization. Repeated Finalize must not destroy resources twice
or leak X errors to the caller's handler. The fallback-success case checks both
creation attempts and normal module startup/cleanup with a live context.
The original successful initialization and repeated-shutdown path also runs
after the injected cases.

The test was first pushed without the production fix as
`b7f4b4981e4590d058fe436d98d889825f259699`.
[Pipeline 946](https://app.circleci.com/pipelines/github/netwarm007/GameEngineFromScratch/946),
Linux job 4390, built successfully but failed LinuxApplicationLifetimeTest:
after a null drawable result, the old implementation still created a context
and violated the first failure boundary. This was an expected regression
failure, not an accepted source revision.

The first production fix, `b66abf01b795282d3f5a76141dd3db0aa9683c04`, passed
the four failure cases but failed the fallback-success case in
[pipeline 947](https://app.circleci.com/pipelines/github/netwarm007/GameEngineFromScratch/947),
Linux job 4394. Investigation found the Display overwrite during XCB window
creation. Preserving that connection returned the complete native regression
to passing in pipeline 948; the fallback assertion was not weakened.

Local Windows ApplicationLifetimeTest, RenderServicesTest, and
RuntimeModuleLifecycleTest passed. Linux production code and the native test
were compiled/executed in CI, not locally on the Windows host.

## Limitations

The failure injection replaces selected API results and queues one real X error;
it does not exhaust driver allocation failures, disconnects, concurrency, or
resource exhaustion. The global X error handler is exercised sequentially,
not under concurrent GLX initialization. X display opening and framebuffer
selection failure paths are not generally hardened by this change.

This completes the Linux GLX sub-checkpoint of roadmap stage B, not equivalent
D3D12/Metal failure coverage or all of stage B. Windows OpenGL, D2D, Vulkan,
Android, SDL, WebAssembly, and other unlisted configurations were not
runtime-verified. Android remains disabled in CircleCI.

This record verifies only the full source revision above, not the
documentation-only commit adding it or a later merge. No PR was created for
this intermediate checkpoint.
