in place. Native macOS Vulkan application builds also build the Metal shader
library and check restoration of a deliberately removed bundled Vulkan shader.

substitute libraries and a baker. Both fixture clients must link every platform
backend, and staged/installed assets must include the required shader variants.
macOS additionally checks bundle contents and Metal library resources. An
asset edit followed by rebuilding/reinstalling must refresh scene contents.
The test is labeled `fast`, but ran inside the full platform suites here.

The same fixture regression also passed locally using session-scoped
CMake/Ninja and Zig's C++ compiler, with C++ module scanning disabled for that
toolchain. This is supplementary build-graph evidence, not a native engine
build or a substitute for the platform jobs.

## Limitations and follow-ups

- Normal static linking may discard unused backend objects. M2 factories must
  reference implementations before complete executable-level availability can
  be claimed. There is no runtime selector or switch operation in this revision.
- Real macOS application bundles were exercised. Feature-branch CI did not
  generate the native project installers; Windows/Linux installation coverage
  here uses the production installation helpers with fixture clients. Installed
  native distribution checks remain part of M5 rollout.
- Missing-runtime availability, explicit backend startup, state-preserving
  reconstruction, cross-backend transitions, and failure recovery remain M2-M4
  work. This record does not verify those future operations.
- Windows native Vulkan/OpenGL selection, physical Retina/mixed-DPI behavior,
  and interactive floating-window/input coverage are not established by these
  artifacts. Vulkan's outstanding acceptance remains governed by its own plan.
- The legacy trimmed build and desktop cross-compilation are not validated by
  this complete-build run. The latter explicitly requires a future host-tool
  path rather than running a target-platform MaterialBaker.

Open effort-wide limitations remain in the roadmap with their owning
checkpoint. A later documentation-only commit adding this record does not
verify a different source revision.
