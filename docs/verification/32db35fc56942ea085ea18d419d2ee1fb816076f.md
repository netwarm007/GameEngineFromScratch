## Accepted boundary

BilliardGameLogic takes required borrowed `ISceneManager&` and
`IPhysicsManager&` references instead of downcasting Application to locate
services. The composition root constructs both services before logic, so they
outlive the consumer. The inactive legacy game configuration now exposes an
explicit factory with those dependencies rather than global default construction.

Loading preserves `Scene/billiard.ogex` and propagates the scene service result.
Each held-left callback resolves the current `pbb_cue` node and requests the
existing (-100, 0, 0) central force. Missing/expired nodes and nodes without
bodies retain their normal no-action behavior. Right-drag rotation retains its
signs and per-axis window-size scaling. Application still provides configuration
through IApplication, but loading and cue force routing no longer require it.

This accepts D4b in the
[modularization roadmap](../architecture/modularization-roadmap.md). No new
injection framework, Application rewrite, input-system change, physics solver
change or shader/rendering change is included.

## Regression evidence

physics services and a plain IApplication, without a native window/backend.
It covers:

- Scene path, successful loading, fresh initialization and exact load-error
  propagation without Application.
- Cue lookup on every event, exact force components, current-node routing
  after same-name replacement and normal no-body results.
- Missing/expired cues without force calls or retained cue ownership.
- Left-drag filtering, right-drag signs and independent width/height scaling.
- Current configuration and scene-camera replacement, absent scenes/cameras,
  and separation of camera input from physics requests.

checks fail. Restoring it passed all nine focused local Debug tests:
BilliardGameLogicTest, ViewerLogicTest, InputManagerTest,

## Limitations

Synthetic input does not establish native OS event delivery, exhaustive ImGui
focus/capture paths or every camera orientation. Fake physics validates
request routing, not integration; native Billiard regression supplies separate
movement evidence. The legacy configuration factory is compile-checked, not
wired into the current native executable. Configuration access remains an
Application dependency with the existing valid-dimensions precondition.

Linux terminates Viewer after capture; ordinary macOS Viewer capture is
best-effort. Separate Windows/macOS scene-cycle steps enforce normal exit.
Existing optional scene assets, shadow differences and performance are outside
D4b. Android is disabled. Vulkan, GLES and unlisted backends are not accepted.
