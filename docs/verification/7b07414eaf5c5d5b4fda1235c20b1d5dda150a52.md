## Scope

From the [memory allocator roadmap](../architecture/memory-allocator-roadmap.md):
`MemorySystem` owns a private page source and now lives from before module
initialization until after module finalization (also released after a failed
start). `EngineAllocation` (`SetEngineAllocator`, `EngineAllocate/Free`,
`EngineStlAllocator`, `MakeEngineShared`) tags each block with an allocator
generation so it returns to its origin heap; unhooked, exhausted or stale
cases fall back or leak instead of crashing. Pilot types are the D3D12 and
OpenGL `DrawBatchContext` subclasses. `EngineAllocationTest` covers hook
on/off, generation mismatch, fallback, shared_ptr lifetime and threads (also
run locally under ASan/UBSan, `-O2` and TSan); `ApplicationLifetimeTest`
checks the system outlives module finalization.

## Tested configurations

- Linux and Windows: engine built with `-DUSE_ENGINE_ALLOCATORS=ON
  -DENABLE_ALLOCATOR_TRACKING=ON`.
- macOS: switch OFF (default).

## Limitations

- No rendering or screenshot was inspected; CI does not demonstrate identical
  frames with the switch ON.
- `DrawBatchContext` exceeds 512 B, so the pilot objects are served by TLSF,
  not the small-object cache.
- `SetEngineAllocator` must change only while no thread allocates through it.
- The ON configuration is not verified on macOS.
