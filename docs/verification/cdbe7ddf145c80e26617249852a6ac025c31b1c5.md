# Windows full-CI resource optimization

Tested source revision: `cdbe7ddf145c80e26617249852a6ac025c31b1c5`.

## Exact-revision full CI

[CircleCI pipeline 1060](https://app.circleci.com/pipelines/gh/netwarm007/GameEngineFromScratch/1060/workflows/6ae0aa1b-2a28-46d6-909d-0017eb28a8f3),
run `ddfccbf5-9324-4bf8-b443-9defc44ee8ea`, used the full `build-and-test`
workflow on `agents/optimize-windows-ci-runtime`. The complete workflow
succeeded in 39 minutes 47 seconds and was not a quick/fast-label-only run.

| Platform | Tested backend | Job | Result |
| --- | --- | --- | --- |
| Windows | D3D12 / Win32 | 4762 | Debug and Release dependencies, engine builds and tests passed; Viewer, scene replacement and Billiard regressions passed |
| Linux | OpenGL / GLX / Xcb | 4763 | Debug and Release dependencies, engine builds and tests, screenshots and coverage passed |
| macOS | Metal / Cocoa and MoltenVK | 4764 | Debug and Release builds, Viewer, Billiard and Vulkan/MoltenVK verification passed |
| Linux Vulkan | Vulkan / lavapipe and native XCB | 4765 | Shader ABI, compute, resource, pipeline, graphics, GUI, swapchain and native application verification passed |

The Windows job changed from the default `windows.medium` executor to
`windows.large` and from `CMAKE_BUILD_PARALLEL_LEVEL=2` to 8. The full
`windows.medium` baseline job 4761 on revision
`e8777e81662bf7f769e05f52ac1706bea2ed14af` ran for approximately 45 minutes
15 seconds. Job 4762 ran for 39 minutes 22 seconds, a 5 minute 53 second
reduction, or approximately 13 percent.

| Windows step | Baseline | Optimized | Change |
| --- | ---: | ---: | ---: |
| Build Engine (Debug) | 7.67 min | 4.58 min | -40.3% |
| Build Engine (Release) | 7.99 min | 4.90 min | -38.7% |
| Build Windows dependencies (Release) | 6.50 min | 6.17 min | -5.1% |
| Build OpenAL (Debug) | 3.40 min | 3.23 min | -5.0% |

The optimized job reached 100 percent of the 8-core limit and peaked at 26
percent of 30 GiB memory. This confirms that the added CPUs were used without
approaching the larger executor's memory limit.

## Artifact observations

Windows, Linux and macOS retained Viewer, scene-cycle and Billiard artifacts.
The Windows Viewer captures showed both docked panels contained inside the
main viewport, without overlap or clipping. Scene cycle 1 rendered the Billiard
scene and scene cycle 2 restored the original scratch scene. The Windows
Billiard capture rendered the table and physics result screen without a
missing panel or blank frame. Linux and macOS screenshot artifacts and the
Vulkan/MoltenVK image sets were also present.

## Limitations

This measurement compares one successful full run on each revision. The larger
resource class increases available compute and may increase credit usage;
credit efficiency was not established by this two-run comparison. OpenAL and
parts of Release dependency preparation retain substantial sequential work,
so they improved less than the two engine compilation steps. Explicit
`--parallel 2` regression builds and all quick/full workflow semantics remain
unchanged. Release still receives compile-and-test coverage but not duplicate
visual regressions. Android remains disabled, and Emscripten/WebAssembly,
FreeBSD, CUDA and OptiX are outside this record. Linux software Vulkan and
OpenGL results do not establish hardware-driver parity.

The documentation-only commit carrying this record uses `[ci skip]`. It does
not supersede or count as a separate verification of the tested source revision.
