## RHI diagnostics smoke

`--list-rhi` exits 0 and lists availability; `--rhi bogus` and repeated `--rhi`
exit nonzero with the expected diagnostics, on all three platforms. The macOS
`--list-rhi` correctly reports `vulkan: runtime unavailable` in the plain smoke
environment (no MoltenVK loader on the default search path), demonstrating the
availability probe and loader isolation rather than a failure.

## Vulkan coverage migration and retirement

- `build_linux` now configures `-DVULKAN_RHI_TESTS=ON`; the integrated suite is a
  **superset** of the retired job's tests. At the pre-retirement revision
  `1893edb6` (pipeline 1121) the specialized job ran 8 Vulkan tests
  (ShaderAbi, Compute, Resources, Pipelines, Graphics, Gui, SwapchainLifecycle,
  FrameLoop); `build_linux` ran all 8 plus `TEST_VulkanLoaderTest` and
  `TEST_LinuxVulkanApplicationLifetimeTest`. All pass at this revision.
- The retired job's opt-in `VULKAN_APPLICATIONS` Viewer/Billiard captures are
  replaced by the runtime-selection Viewer/Billiard Vulkan matrices above, which
  run each backend from the same executable instead of a second application tree.
- macOS retains its in-job MoltenVK rendering/presentation verification and the
  opt-in Vulkan application bundle-asset-refresh check.

## Limitations and remaining scope

- M2 (startup selection) is complete with this work step; M3 (isolated
  reconstruction), M4 (cross-backend switching) and M5 (UI/application rollout)
  remain separate checkpoints, each requiring human confirmation.
- Cross-backend capture bounds assert scene/layout agreement under software
  rasterization, not pixel-exact equivalence across backends.
- Linux runtime selection retains the SDL OpenGL host (XCB has no ImGui platform
  input backend); XCB ImGui parity remains the tracked prerequisite for the
  agreed XCB-only host.
- Deliverable acceptance (all roadmap tasks + three-platform CI + PR) is not
  claimed by this per-revision verification record.
