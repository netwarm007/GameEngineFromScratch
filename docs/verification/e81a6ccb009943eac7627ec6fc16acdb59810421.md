## Scope

From the [memory allocator roadmap](../architecture/memory-allocator-roadmap.md):
`TlsfAllocator` and `BuddyAllocator`. Tests cover configuration rejection,
splitting and coalescing, bin boundary sizes, alignment (TLSF up to 4096 with
leading-gap splitting, buddy block alignment), exhaustion and overflow,
fragmentation, invalid and double frees, `FreeAll`, and randomized
allocate/free workloads that verify data integrity and call each allocator's
`Check()` heap-invariant walk. They also ran locally under ASan/UBSan on
Linux with debug and optimized flags.

## Limitations

- The allocators are not used by other engine modules yet; no rendering
  backend or screenshot behavior was exercised or changed.
- Both are single-threaded with fixed capacity.
- TLSF good-fit lookup can refuse a request within about 1/32 of the only
  free block; its free-pointer checks inspect headers and can be fooled by
  crafted user data.
- Buddy blocks waste up to 50% and support alignment only up to 4096 bytes.
- Debug fill patterns are checked only in builds defining `_DEBUG`.
