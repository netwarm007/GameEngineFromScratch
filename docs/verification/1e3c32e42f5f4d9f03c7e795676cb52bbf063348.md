## Fix chain (real-machine findings → resolution)

| Finding | Root cause | Fix |
| --- | --- | --- |
| 1 | Recovery failed when the window was already destroyed | `recreateWindow \|= windowAbsent` |
| 2 | "Switch complete" markers seemingly missing | Retracted: `Stop-Process -Force` cout-flush artifact |
| 3 | Failure dialog / progress modal never shown (synchronous switch completes in one frame boundary) | Controller `ConsumeSwitchFailure` event queue consumed by GUI |
| 5 | Backend menu vanished post-switch; provider null on fresh GraphicsManager; OverlayPass captures provider at construction | Re-bind provider after reassignment + refresh `m_pRhiSelection` from manager each `GuiSubPass::Draw` |
| 4 (Linux/macOS) | Recovered frame gray | macOS: failure-modal dimming overlay (suppress in CI recovery captures); Linux: no current GL context after ImGui multi-viewport displaces it (SDL frame-start `MakeCurrent`) |
| clearColor | `Frame::clearColor` is Vector3f; Metal/OpenGL read `[3]` (out-of-bounds garbage alpha) | Use opaque clear alpha `1.0f` (align Vulkan/D3D12) |
| CI Windows matrix diff | Failure-modal dimming not suppressed in Windows matrix runs | `GEFS_RHI_SWITCH_SUPPRESS_FAIL_DIALOG` for Windows matrix/preflight |
| CI Windows OpenGL switch fail | Runner has no GPU (GDI Generic GL 1.1); llvmpipe set only for opengl-initial pairs | llvmpipe override for every OpenGL-containing pair |
