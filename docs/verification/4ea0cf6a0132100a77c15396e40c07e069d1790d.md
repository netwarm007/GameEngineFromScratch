## Real-driver evidence (supplementary)

On a real Windows desktop (AMD Radeon integrated GPU, Vulkan 1.4.315, driver
26.11.2) the AMD driver lacks `VK_KHR_swapchain_maintenance1` /
`VK_EXT_swapchain_maintenance1` and `VK_KHR_surface_maintenance1` (not promoted
to Vulkan 1.4 core — a genuine gap). At this revision:

- `--rhi vulkan` with old SDK headers (1.2.182) hits the compile-time header
  gate; with 1.4.363 headers it reaches the runtime check
  (`get_surface_capabilities2` passes, then surface-maintenance1 rejected).
  Both exit -1 within seconds with a clear diagnostic, no crash/hang/dialog —
  the M4.4 explicit-failure contract verified on real hardware.
- `--list-rhi` exits 0 with correct probe semantics; `--rhi d3d12` renders on
  the AMD hardware path (Feature Level 12.1, no WARP), self-capture exits 0,
  non-black frame.

Real-desktop cross-backend A/B/A switching was additionally exercised on the
same machine (Viewer Debug built at `a5ce6ecd`, a docs-only delta from this
revision — the switch code is identical; Vulkan 1.4.363 headers):

- **d3d12 → opengl → d3d12** (`--rhi d3d12 --rhi-switch opengl@120,d3d12@300`):
  console markers `RHI switch request opengl: accepted` → `RHI switch complete:

## Limitations (this revision)

- Verification covers the CI-feasible software-rasterizer pairs and the real
  AMD D3D12/Vulkan-rejection path. Hardware GPU switching on Windows
  (D3D12↔OpenGL↔Vulkan on a real driver) and Metal↔Vulkan on real Apple silicon
  are not exhaustively exercised by CI; macOS runs on the CI paravirtual device.
- The AMD Windows driver cannot run the Vulkan backend (maintenance1 absent);
  a fallback present-retirement path without swapchain-maintenance1 is a
  candidate follow-up, not implemented here.
- Terrain texture tiles beyond `area_1_0_0.png` are not committed (known,
  documented in the Vulkan plan); the engine falls back gracefully (255
  non-fatal diagnostics).
- Installed-distribution validation and Retina/mixed-DPI real-machine acceptance
  remain M5 scope (best-effort installed checks; DPI evidence carried over from
  the Vulkan plan).
- Android and WebAssembly are unmaintained/disabled and not part of this gate.
