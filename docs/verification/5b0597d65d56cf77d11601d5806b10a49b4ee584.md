## Scope

From the [memory allocator roadmap](../architecture/memory-allocator-roadmap.md):
`MemorySystem` (a `RoutingAllocator`, optionally wrapped by a
`TrackingAllocator` that reports leaks on destruction), owned by
`BaseApplication`, and the CMake options `USE_ENGINE_ALLOCATORS` and
`ENABLE_ALLOCATOR_TRACKING` (both default OFF). `MemorySystemTest` covers the
plain and tracked stacks, leak reporting and page return on destruction, and
an unusable page source. `ApplicationLifetimeTest` (switch ON only) checks
that the system exists while running, survives a rejected re-initialization,
and is released before the memory manager finalizes on both shutdown and
failed-initialization rollback, and that an unusable page source leaves it
unset. `MemorySystemTest` also ran locally under ASan/UBSan and at `-O2`.

## Tested configurations

- Linux: engine built with `-DUSE_ENGINE_ALLOCATORS=ON
  -DENABLE_ALLOCATOR_TRACKING=ON` (via `CMAKE_ARGS` in `scripts/build-ninja.sh`).
- Windows and macOS: switch OFF (default); the ON code path compiled and ran
  only on Linux.

## Limitations

- No engine module allocates from `MemorySystem` yet (M8.3 onward); no
  rendering behavior or screenshot was exercised or changed.
- The ON configuration is not verified on Windows or macOS.
