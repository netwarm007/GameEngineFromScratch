## Boundary and failure regression

- Scene objects no longer read assets, decode images, or own asynchronous
  tasks. Scene services link without asset IO, platform asset initialization,
  or the image decoder target.
- The injected resource loader prepares every material channel, including the
  default material, as well as skybox faces and terrain tiles. Shared texture
  objects are prepared once; already prepared images are reused.
- Renaming a texture invalidates its image. Missing files use one shared
  missing-texture image per loader, with the expected icon pixels and format.
  Unsupported formats and an unavailable fallback report loading failure.
- Resource preparation failure preserves the current scene and revision.
  Temporarily bypassing preparation made the scene service regression fail;
  the production implementation was restored and tests passed.
- The preceding source revision failed Linux linking in pipeline 887 because
  the GUI PNG decoder had relied on zlib arriving through SceneGraph.
  Direct decoder consumers now declare the shared ImageDecoders dependency.
  Pipeline 888 verifies that correction without reintroducing a dependency
  from scene data to decoders.

## Limitations

Windows CI does not test Billiard's default OpenGL backend. Android is disabled;
WebAssembly, Vulkan, CUDA, and other unlisted configurations are not verified
by this record. Resource preparation completes before a scene is published;
this is not a streaming or cancellation implementation. Screenshots and the
fixed-shot regression do not establish full rendering or physics correctness,
nor do they verify every possible image file or malformed decoder input.
This record verifies only the source revision above, not a subsequent merge
or the documentation-only commit adding this file.
