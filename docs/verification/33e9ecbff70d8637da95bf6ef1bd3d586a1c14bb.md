## Vulkan GPU evidence

The llvmpipe job passed `TEST_VulkanShaderAbi`, `TEST_VulkanCompute`,
`TEST_VulkanResources`, `TEST_VulkanPipelines`, `TEST_VulkanGraphics`, and
`TEST_VulkanFrameLoop`. Its CTest artifact contains zero validation messages
and zero validation-error/VUID markers.

Production VulkanGraphicsManager/RHI/pipeline code runs the existing shared
GraphicsManager::BeginScene scheduler, ForwardGeometryPass and its geometry/sky
subpasses, and ShadowMapPass. No substitute Vulkan scene renderer or copied
lighting/shadow algorithm is used.

- Four BASIC/PBR scene checks cover one- and four-sample targets, actual
  uploaded material-gradient UVs, independent index groups, default vertex
  streams, frame/model/light uniforms, visibility, and depth occlusion with a
  farther differently colored mesh deliberately drawn last.
- Four PBR shadow-receiver checks exercise point, spot, area, and directional
  shadows. An off-axis receiver darkens while vertically displaced and
  independently lit controls remain unchanged.
- Twenty-four point-shadow face checks cover two translated lights, reversed
  independent cube indices, all six faces, and both the geometry and shared
  single-face vertex variants. Unequal off-axis occluders match world-space
  radial depth within 0.000002; center texels stay clear. Prepared light
  indices remain unchanged, and rendering the second cube preserves the first.
- The standard omni definition uses the shared single-face variant for devices
  without geometry shaders and for the upstream macOS Metal-stage selection.
  The single-face regression selects that same production variant explicitly;
  it does not establish MoltenVK runtime support.
- Packed environment checks verify visible faces, generated visible mips,
  irradiance in cube 0 mip 1, and every supplied radiance face/mip in cube 1.
  Six actual rendered sky directions check face selection, spatial orientation,
  and exposure/gamma output within 1.5 RGBA8 levels. A black-environment control
  distinguishes actual PBR irradiance/radiance/BRDF consumption.
- Four-sample resolve matches analytic 3/4 edge coverage within three RGBA8
  levels and a fully covered single-sample control within two levels.
- Repeated material references share the existing material cache instead of
  allocating scalar/image textures per draw group.
- Abandoned command sessions restore layouts without submitting their recorded
  writes. Overlapping immediate transfers and tracked-image destruction are
  rejected. Scene reload after an abandoned render pass, resize, stale handles,
  repeated finalization, and GPU resource destruction remain passing.
- Native Xcb frame-loop coverage separately checks presentation-fence retirement,
  resize/minimize/restore, aborted acquisition followed by safe recreation/retry,
  and repeated shutdown. It is separate from the headless scene-rendering test.

Five supported headless tests also passed locally on Windows AMD after a clean
build; shared GLSL stage-link/MSL generation compatibility passed. A local
negative control using negative-height shadow viewports failed the real PBR
off-axis receiver assertion. Restoring positive-height shadow viewports and
clockwise shadow front faces passed with zero validation/VUID markers.

## Limitations

- Vulkan Viewer/Billiard selection, final swapchain/UI composition, ImGui
  renderer ownership, icons/previews/debug textures, and supported floating
  viewports remain checkpoint 4 work.
- Scene-rendering tests are headless; native presentation uses a separate Xcb
  regression. Native Windows Vulkan WSI and MoltenVK/Cocoa remain unverified.
  The installed local SDK cannot run the strict maintenance-aware native loop.
  Passing Metal jobs do not verify MoltenVK.
- CI Vulkan is software rendering, not hardware acceptance. Generated scene
  and environment fixtures do not establish real Vulkan application-asset
  integration; that requires checkpoint 4 captures.
- Reference CI supports D32 linear filtering. Its capability-selected nearest
  shadow-sampler branch was not selected in this job. Other backends retain
  their existing sampler binding; Vulkan material filtering is not downgraded.
- The renderer requires the shared 28800-byte light uniform range. Unsupported
  vertex/primitive formats, image packing, and sample counts fail explicitly.
  Initialization compute covers the active BRDF pass, not dormant raytrace
  dispatch or exhaustive BRDF boundary accuracy.
- Disabled Android is not covered.
