## Vulkan evidence

The retained llvmpipe CTest log reports passing `TEST_VulkanShaderAbi`,
`TEST_VulkanCompute`, `TEST_VulkanResources`, `TEST_VulkanPipelines`, and
`TEST_VulkanFrameLoop`, with no validation-error/VUID markers.

The new pipeline regression exercises the production Vulkan pipeline manager
and RHI, with the real asset loader and shared-HLSL SPIR-V:

- Missing assets, wrong shader-stage names, mismatched entry-point binaries,
  invalid SPIR-V magic, and currently unenabled vertex-layer output fail before
  invalid module creation.
- Registry initialization failures at PBR fragment loading and then BRDF
  compute loading release earlier completed pipelines and allow retry of the
  same registry. Per-pipeline scoped allocations also roll back.
- Production BRDF dispatch writes a 512-by-512 image. Selected interior samples
  and repeated channels match the independent CPU reference within 0.001.
- BASIC/PBR graphics pipelines are created against an offscreen render pass.
  Their creation alone is not evidence of scene rendering or material binding.
- Shared texture-debug stages draw a four-color offscreen fixture using
  separate position/UV streams. Every output texel checks orientation with a
  negative-height viewport and counterclockwise front faces; front-culling
  checks the cleared result instead.
- Unregistering the source definition and repeated finalization release GPU
  objects even when a shared reference retains the pipeline-state object.
- Aborted immediate recording releases its command buffer. Existing resource,
  ABI, compute, and strict native-presentation regressions remain passing.

No Vulkan-only shader algorithm or scene pass was introduced.

## Limitations

- Vulkan CI uses software rendering under Xcb/Xvfb. Local clean-built Windows
  headless tests passed on AMD, but native Windows Vulkan WSI and MoltenVK/Cocoa
  Vulkan remain unverified. The Metal job does not verify MoltenVK.
- GraphicsManager scene/pass integration and GPU consumption of shared
  frame/batch/light arenas are not implemented by this increment.
- BASIC/PBR scene output, skybox integration, six-face/multi-light shadow depth
  and sampling, MSAA rendering, Vulkan applications, and ImGui remain pending.
- Vertex-layer feature enablement or the planned shared single-face adaptation
  remains required for devices without the geometry path.
- BRDF interior samples do not establish numerical accuracy at the
  near-zero-roughness LUT boundary.
- Disabled Android is not covered.

This record verifies only this source revision, not the documentation-only
record commit or a subsequent merge. Earlier revision records remain unchanged.
