## Scope and focused regression

RuntimeModuleGroup now handles registration and lifecycle only. TickFrame
traverses a caller-supplied ordered view without retaining modules or changing
their lifecycle. BaseApplication passes the current initialized-module view,
preserving the previous default update order. Platform event polling and
backend frame setup/presentation were not changed.

The standalone runtime regression verifies independent frame selection and
ordering, unchanged registration and reverse cleanup order, suppression of
updates before initialization and after failure/finalization, retry, and fresh
participants after a new lifecycle. A clean negative build with reversed frame
traversal failed the ordering assertions. The production traversal was restored,
clean-built, and passed.

Local Windows Debug builds of Viewer and Billiard passed, as did the standalone
runtime test and four focused full-project tests: runtime lifecycle/frame
traversal, scene services, physics/scene integration, and GUI layout.
Local D3D12 Viewer and Billiard captures were inspected; both applications
exited successfully and the Billiard shot/collision regression passed.

## Limitations

This checkpoint extracts frame traversal, not a phase-based scheduler, fixed
time step, parallel execution system, or change in simulation/render timing.
The borrowed initialized-module view must not be retained across registration
or lifecycle changes. Explicit frame views require live, initialized modules.

Windows OpenGL, Android, WebAssembly, Vulkan, CUDA, and other unlisted
configurations are not verified by these CI results. Screenshots and the fixed
shot do not establish full rendering or physics correctness.
This record verifies only the source revision above, not a subsequent merge
or the documentation-only commit adding this file.
