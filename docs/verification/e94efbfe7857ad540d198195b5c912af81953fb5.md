# CI source-cache fix (no LFS prune on blobless checkouts)

Tested source revision: `e94efbfe7857ad540d198195b5c912af81953fb5`.

## Exact-revision full CI

[CircleCI pipeline 1068](https://app.circleci.com/pipelines/github/netwarm007/GameEngineFromScratch/1068),
workflow `a2238eb3-0467-4e86-84f2-8d72721824b0`, used the full
`build-and-test` workflow on `ci/fix-blobless-lfs-prune` and succeeded in about
42 minutes; it was not a quick/fast-only run. It repairs the master-only
source-cache step introduced by #80, which failed on all three platforms with
`Prune error: missing object` because `git lfs prune` scans historical blobs
that a blobless checkout does not have.

## Observations

- The change removes `git lfs prune` from the master-only source-cache save
  step on all three platforms, keeps `git gc`, and makes the Windows step
  propagate a nonzero `git gc` exit code via `$LASTEXITCODE`.
- Screenshots for this exact revision were inspected, not just the step
  outcomes: Windows, Linux and macOS Viewer renders show the docked panels
  inside the main viewport without overlap or clipping; both scene-replacement
  cycles (`scene-cycle-1`, `scene-cycle-2`) render the replaced scenes and
  wrote their `scene-ready` markers; Billiard wrote `physics-passed` on all
  three platforms and its after-physics screenshots show the settled table.
- Linux Vulkan (lavapipe) and macOS MoltenVK each report 8/8 CTest cases
  passed. Their Viewer and BilliardGame PPM captures were inspected (converted
  losslessly to PNG for review) and show correct scene and GUI rendering.
- Dependency caches were restored on the branch jobs; the source and ccache
  caches remain master-only saves.

## Limitations

- The master-only `git gc` + source `save_cache` path — the step that previously
  failed — does not run on branch pipelines, so this record verifies the full
  branch scope for this revision but not that master-only path. It first runs
  on the next master push (for example when this fix is merged); a failure
  there would need its own investigation and record.
- Android remains disabled; Emscripten/WebAssembly, FreeBSD, CUDA and OptiX are
  not accepted by this record.
