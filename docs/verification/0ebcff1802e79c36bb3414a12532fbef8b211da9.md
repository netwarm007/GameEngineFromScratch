## Boundary and focused regression

Viewer and Billiard explicitly supply scene and pipeline service references to
their graphics backend. These services outlive the graphics manager; module
registration, initialization order, frame order, and backend projection
conventions are unchanged. Passes continue to receive the backend instance
directly. The default constructor retains the graphics-only mode used by
standalone graphics clients, without discovering Application-registered services.

`RenderServices` contains the coordinator independently of the other managers.
Its regression uses an IApplication test double rather than BaseApplication,
with injected scene/pipeline services and a recording graphics backend. Its
local link dependencies were inspected: no Manager, Application implementation,
or RHI library is linked. ImGui, asset IO, and image decoder dependencies remain.

The regression checks unloaded-scene suppression, a single rendering snapshot
per frame, initial pipeline/backend routing, unchanged-revision rendering,
scene replacement, missing-snapshot retry without discarding the old scene,
frame snapshot cleanup, graphics-only rendering, and explicit initialization
failure when the platform application is missing.

Temporarily disconnecting scene injection made seven regression expectations
fail. Restoring injection and rebuilding returned the test to passing.
The isolated Visual Studio build also exposed a missing asset bootstrap build
dependency; the platform interface now carries that target as well as its
object files, so the regression can build without a platform application target.

Local Windows Debug builds used a session-local CMake harness selecting the
production library and test targets. RenderServicesTest, SceneCameraTest,
SceneLightingTest, SceneServicesTest, GuiSubPassLayoutTest, and
RuntimeModuleLifecycleTest all passed. A full local application configuration
was blocked by missing prebuilt dependencies; actual backend/application checks
were performed using the exact-revision CI builds and artifacts instead.

## Limitations

This checkpoint removes scene/pipeline service lookup from the rendering
coordinator, not every Application dependency in the engine. IApplication still
provides configuration and framebuffer dimensions. Platform/RHI resource
ownership, UI asset loading, and ImGui lifecycle remain in their current layers.
No scheduler, shader, or resource ownership redesign is included.

Windows OpenGL, Android, WebAssembly, Vulkan, CUDA, and other unlisted
configurations are not verified by this pipeline. Screenshots and the fixed shot
do not establish full rendering or physics correctness.
This record verifies only the source revision above, not a subsequent merge or
the documentation-only commit adding this file.
